# 공유 링크 랜딩 페이지 리디자인 - 설계 (Design)

작성일: 2026-08-04
대상: `kcc-links/src/index.js`의 `landing()` 함수(`https://kcc.sidore.org/e/*` 경로에서
서빙되는, 미설치/브라우저 폴백용 HTML 한 장)

## Context
일정 공유(딥링크) 기능의 서버 쪽 랜딩 페이지가 지금은 시스템 폰트 + 텍스트만 있는 매우 기본적인
모습이라, 앱을 처음 접하는 사람에게 신뢰감/완성도를 주지 못한다는 지적이 있었다. 앱 자체는
크림색 배경(`#EDEBE4`) + 흰 카드 위에 붓글씨 스타일 로고("가톨릭 달력" + 4가지 전례색 도트:
초록 `#2E7D32`/골드 `#B59410`/빨강 `#C62828`/보라 `#6A1B9A`)를 쓰는 "모던 에클레틱" 톤을 갖고
있고(`lib/app/theme/app_theme.dart`, `lib/app/theme/liturgical_colors.dart`, `assets/icon/app_icon.png`),
랜딩 페이지에도 이 톤을 입히기로 했다.

## 확정된 결정 (사용자 확인)
- **범위: 시각적 개선만.** 링크에 담긴 실제 일정 내용(날짜/시간/메모)을 페이지에서 디코딩해
  미리보기로 보여주는 기능(콘텐츠 미리보기)은 이번 범위에서 제외한다(YAGNI - 이 페이지는 앱이
  설치된 사용자는 애초에 거의 보지 않는 폴백 화면이라, 콘텐츠 미리보기까지는 과함).
- **디자인 방향: B안(브랜드 히어로형)으로 우선 채택.** 큰 앱 아이콘을 중심에 둔 좀 더
  마케팅 랜딩 페이지 느낌. A안(미니멀 카드형, 상단 전례색 그라디언트 줄 + 흰 카드)은 채택하지
  않았지만 **나중에 다시 쓸 수 있어 파일을 그대로 보존**한다.
- 두 목업 모두 `kcc-links/mockups/`에 저장:
  - `kcc-links/mockups/a-minimal-card.html` (미채택, 보존)
  - `kcc-links/mockups/b-brand-hero.html` (채택, 실제 구현의 시각 기준)
  - 두 파일 모두 `../../assets/icon/app_icon.png`(기존 앱 아이콘)를 참조해 브라우저로 바로 열어
    미리볼 수 있다.

## 설계

### 1) B안(브랜드 히어로형)의 시각 요소
- 배경: 크림 배경 위 살짝 밝은 방사형 그라디언트(`radial-gradient(circle at 50% 0%, #F6F3EC 0%,
  #EDEBE4 55%, #E7E3D8 100%)`) - 단색보다 입체감.
- 앱 아이콘: 128px, 둥근 사각형, 뒤에 옅은 초록색 방사형 글로우(`icon-shell`)로 은은한 강조.
- 제목 "가톨릭 달력": 구글 폰트 `Song Myung`(한글 세리프, 단정하고 격식 있는 느낌 - 가톨릭
  전례력 앱에 어울림), 부제 "전례력과 함께하는 나의 하루".
- 구분선: 좌우 얇은 선 + 전례색 4도트(초록/골드/빨강/보라) - 앱 아이콘의 4도트를 반복해 브랜드
  일관성을 준다.
- 본문: "공유된 일정을 확인하려면 가톨릭 달력 앱이 필요합니다."
- CTA 버튼: 필 형태(`border-radius: 999px`), 브랜드 그린(`#2E7D32`) 배경, "앱에서 열기 →",
  탭 시 살짝 눌리는 애니메이션(`transform: scale(0.96)` on active).
- 하단 안내: "앱이 없으신가요? 설치 후 이 링크를 다시 눌러 주세요." (기존 문구 유지, 색만 옅게).

### 2) 실제 구현 시 기술적 차이점 (목업 대비)
목업은 브라우저 미리보기용이라 두 가지를 실제 `kcc-links/src/index.js` 반영 시 바꾼다.
- **웹폰트**: 목업처럼 Google Fonts(`Song Myung`, `Pretendard`)를 그대로 `<link>`로 불러온다.
  `kcc-links`는 별도 빌드 과정이 없는 단일 JS 파일 워커라, 외부 CDN 링크 방식이 이 구조에
  가장 잘 맞는다(폰트 파일을 워커에 내장하지 않음). 네트워크가 느리거나 폰트 로드가 실패해도
  `font-family` 폴백 체인(`'Pretendard', -apple-system, system-ui, sans-serif`)으로 깨지지
  않는다.
- **아이콘 이미지**: 목업은 리포지토리의 `assets/icon/app_icon.png`(약 900KB PNG)를 상대
  경로로 참조하지만, `kcc-links`는 별도로 배포되는 단일 파일 Cloudflare Worker라 그 파일에
  접근할 수 없고, 900KB 이미지를 Worker 응답에 base64로 인라인하는 것도 무겁다. 실제 구현은
  아이콘을 **인라인 SVG**로 재현한다: 크림색 배경의 둥근 사각형 위에 앱 아이콘과 동일한
  4가지 전례색 도트 + "가톨릭 달력" 글자(또는 캘린더 모양 아이콘 하나 정도의 단순 도형)로
  가볍게 재구성. 네트워크 요청 0개로 즉시 렌더링되고, 기존 워커의 "빌드 단계 없는 단일 JS
  파일" 패턴과도 맞는다.
- **버튼 동작**: 기존과 동일하게 `location.href`를 `catholiccalendar://e/`로 치환하는 인라인
  `onclick` 로직을 유지한다(변경 없음).

### 3) 변경 파일
- `kcc-links/src/index.js`의 `landing()` 함수 본문만 교체(다른 라우트: AASA/assetlinks/health는
  변경 없음).
- `kcc-links/test/well_known.test.js`의 "`/e/<payload>` 랜딩은 HTML + 앱 열기/설치 안내" 테스트가
  현재 어떤 문자열을 검증하는지 확인 후, 새 마크업에서도 같은 문구(또는 동등한 표현)가 유지되는지
  맞춰준다. 테스트가 깨지면 문구를 유지하거나 테스트를 새 마크업에 맞게 갱신.

### 4) 배포
- 코드 변경 후 커밋만으로는 실제 `kcc.sidore.org`에 반영되지 않는다. 사용자가 Cloudflare
  대시보드에서 `kcc-links` Worker의 코드를 다시 붙여넣고 배포해야 한다(이전에 안내한 대시보드
  배포 절차와 동일).

## 스코프 밖 (참고, 지금 조치 불필요)
- 콘텐츠 미리보기(공유된 일정의 날짜/시간/메모를 랜딩 페이지에서 디코딩해 보여주기) - 사용자가
  범위에서 제외하기로 결정. 나중에 원하면 별도 설계로 다시 논의.
- A안(미니멀 카드형)은 보존만 하고 이번엔 구현하지 않음.

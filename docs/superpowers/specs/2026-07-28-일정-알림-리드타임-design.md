# 일정 알림 리드타임(사용자 지정 + 복수) - 설계 (Design)

작성일: 2026-07-28
브랜치: `feature/일정-반복`에서 이어서

## Context
현재 개인 일정/축일 알림은 `CalendarEvent.notify`(bool) 하나로 **전날 21:00 + 당일(시작 시각, 종일은
09:00)** 고정 2건을 예약한다(`notifications_mobile.dart` `_remindersFor`, `_dayBeforeHour=21`,
`_dayOfHour=9`). 사용자는 알림 시점을 직접 고르고(리드타임), 한 일정에 **알림을 2개까지** 두고 싶어 한다.

## 확정된 결정 (사용자 확인)
- 리드타임 8종: **5분 / 10분 / 30분 / 1시간 / 2시간 / 1일 / 2일 / 1주일 전**.
- 기준(혼합):
  - **분/시간 단위(5분~2시간 전)** = 일정 **시작 시각 기준**으로 정확히 빼기(정밀).
  - **일/주 단위(1일/2일/1주일 전)** = 해당 날 **아침 09:00** ("1일 전 = 전날 아침 9시").
- **종일 일정**: 시작 시각이 없어 분/시간 리드는 제공하지 않음(일/주 단위만).
- **최대 2개** 알림(기본 1개 + 추가 1개).
- 기본값 = **[1일 전]** 단일.
- 하위호환: 기존 `notify=true` 이벤트는 `[1일 전]`로(전날21시+당일에서 변경). `notify=false`는 알림 없음.
- 일정 편집기 + 축일 편집기 **공통** 적용(둘 다 같은 `CalendarEvent`/알림 경로).

## 설계

### 1) 리드타임 enum - 신규 `lib/features/events/model/reminder_lead.dart`
```dart
enum ReminderLead { min5, min10, min30, hour1, hour2, day1, day2, week1 }
```
- `String get displayName` ('5분 전' ... '1주일 전').
- `bool get isSubDay` (min5~hour2 = true; day1/day2/week1 = false).
- `Duration get subDayDuration` (min5=5m ... hour2=2h; day-based는 사용 안 함).
- `int get dayOffset` (day1=1, day2=2, week1=7).
- `String get storageValue => name;` + `static ReminderLead? fromStorage(String?)`.

### 2) 모델 - `lib/features/events/model/calendar_event.dart`
- 필드 추가: `List<ReminderLead> reminders`(기본 `const [ReminderLead.day1]`). `notify`(bool)는 **마스터
  on/off**로 유지(끄면 예약 안 함).
- `copyWith`/`toJson`/`fromJson` 확장:
  - toJson: `'reminders': [for (final r in reminders) r.name]` (항상 기록, 최소 1개).
  - fromJson: `reminders` 있으면 파싱(빈 리스트면 `[day1]`로 보정), 없으면(레거시) → `[day1]`.
- 불변/정합: reminders는 항상 1~2개, 최소 `[day1]` 보장(편집기가 강제).

### 3) 알림 시각 계산 - `ReminderLead`의 헬퍼(또는 별도 순수 함수)
`DateTime? reminderTime(ReminderLead lead, DateTime occurrenceDate, String? time)`:
- `time`(HH:mm) 있으면 timed, 없으면 all-day.
- lead.isSubDay:
  - timed: `start = occurrenceDate + time`; return `start - lead.subDayDuration`.
  - all-day: return null(분/시간 리드는 종일에 무의미 - 스케줄러/에디터에서 애초에 제외).
- lead day-based: return `DateTime(occurrenceDate.year, occurrenceDate.month, occurrenceDate.day - lead.dayOffset, 9, 0)`.
- 순수 함수 → 단위 테스트 용이(TZ 변환은 스케줄러가 담당).

### 4) 알림 스케줄링 - `notifications_mobile.dart` `_remindersFor`
- 고정 `dayBefore(21시)/dayOf` 로직 제거. 대신 각 **회차(occurrence)** 날짜 × `e.reminders`의 각
  리드마다 `reminderTime(...)`로 시각 계산 → `tz.TZDateTime`로 변환 → **미래분만** `_Reminder` 추가.
- all-day + sub-day 리드는 null → 건너뜀.
- 상한/회차 유지: 전체 `_maxScheduled=60`, 이벤트별 `_maxOccurrencesPerEvent=4`(반복). `_dayBeforeHour`는
  더 이상 안 씀(제거), `_dayOfHour=9`는 day-based 09:00 앵커로 재사용.
- 메시지: `'내일/오늘'` 프리픽스는 임의 리드에 안 맞으므로 제거. 제목 `'$typeLabel · ${e.title}'`
  (typeLabel 축일/일정), 본문 = 일정 시각 요약(`종일` 또는 `HH:mm`) + 메모 접미(기존 suffix 재사용).

### 5) 편집기 알림 섹션 - `event_editor_sheet.dart`(+ `saint_feast_editor_page.dart`)
- 기존 "알림" 스위치(시스템 권한 흐름) 유지. **켜졌을 때** 아래에:
  - **알림 1** 행: 현재 리드 표시(예 "1일 전"), 탭 → 리드 선택 시트.
  - reminders 1개면 하단 **"+ 알림 추가"**(2번째 리드 추가, 기존과 다른 기본값 제안).
  - reminders 2개면 **알림 2** 행(선택 + 삭제 X). "+ 추가" 숨김(최대 2).
- 리드 선택 시트: 종일이면 일/주(1일/2일/1주일 전)만, 시간 지정이면 8개 모두.
- 종일 토글 시: reminders에서 분/시간 리드 제거(전부 무효면 `[day1]` 보정).
- 상태: `List<ReminderLead> _reminders`(initState에서 `existing?.reminders ?? [day1]`), 저장 시 event에 반영.
- 축일 편집기는 항상 종일(time=null)이므로 일/주 리드만 노출.

### 6) 저장소/백업
- `event_repository`/백업은 toJson/fromJson 위임 → 모델(2번)만 확장하면 자동 포함.

## 주요 파일
- 신규: `lib/features/events/model/reminder_lead.dart`.
- 수정: `calendar_event.dart`(필드/직렬화/copyWith), `notifications_mobile.dart`(`_remindersFor` 재작성),
  `event_editor_sheet.dart`·`saint_feast_editor_page.dart`(알림 UI), 필요 시 알림 페이크(테스트) 시그니처 무관.

## 범위 밖 (YAGNI)
- 3개 이상 알림, 일 단위 앵커 시각(09:00) 사용자 설정, 반복 종료/스누즈, 위젯 반영.

## 검증 (End-to-End)
1. 단위: `reminderTime` - timed(1시간 전 = 시작-1h), day-based(1일 전 = 전날 09:00), all-day sub-day=null,
   2일/1주일.
2. 단위: 모델 직렬화/하위호환(reminders 없으면 [day1], notify=false 유지).
3. 스케줄러: reminders 2개 × 회차에 대해 미래분만, 상한/회차 준수(페이크 플러그인 or 순수 헬퍼 검증).
4. 위젯: 편집기 알림 on → 알림1 표시, "+추가" → 알림2, 최대 2, 삭제, 종일 시 분/시간 숨김.
5. `flutter analyze` 무경고, `flutter test` 통과.

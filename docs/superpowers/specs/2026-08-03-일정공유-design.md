# 일정 공유 (딥링크) - 기능정의서 / 설계 (Design)

작성일: 2026-08-03
브랜치: `feature/일정공유` (develop 기준)

## Context
개인 일정은 기기 로컬(`shared_preferences`)에만 저장되고 서버가 없다. 사용자는 자신이 등록한
개인 일정을 다른 사람에게 링크로 공유하고, 받은 사람이 링크를 눌러 **가톨릭 달력 앱**이 열리며
그 일정을 **자기 달력에 등록**해 상세화면에서 볼 수 있기를 원한다.

현재 상태(확인 완료):
- iOS: `catholiccalendar://` 커스텀 URL 스킴만 등록됨(Info.plist). Android: 딥링크 intent-filter 없음.
- Dart: 들어오는 링크 수신 처리 없음. 카카오 SDK/공유 패키지 없음(현재 go_router, url_launcher만).
- `CalendarEvent` 모델과 상세화면(day_detail), 일정 편집기(`showEventEditor`)는 이미 존재.

## 확정된 결정 (사용자 확인)
- **전송 방식**: https 유니버설 링크(iOS)/앱 링크(Android). 카카오톡 채팅에서 커스텀 스킴은 안 눌리므로
  https 링크를 쓴다. 커스텀 스킴 `catholiccalendar://` 는 폴백으로 유지.
- **도메인**: `kcc.sidore.org` (Cloudflare Worker 커스텀 도메인/라우트로 연결).
- **공유 수단**: OS 기본 공유 시트(`share_plus`) - 카카오톡 포함 모든 앱으로 링크+요약 텍스트 전송.
  (카카오 링크 리치 카드 SDK는 범위 밖.)
- **데이터 전송**: 일정 정보를 **링크 안에 담아** 전달(서버 저장 없음).
- **공유 범위**: 개인 일정만, **단건(single occurrence)**. 반복 규칙/축일은 범위 밖.
- **보내는 진입점**: 상세화면의 개인 일정 행에 "공유" 버튼(등록 후 상세로 돌아오면 바로 공유 가능).
- **받는 흐름**: 별도 미리보기 시트 없음. **일정 편집기를 "추가 모드"로 열어 값 자동 입력** ->
  사용자가 저장 -> 상세화면 노출.
- **카테고리**: payload에 이름+색을 **담되(향후 사용 대비)**, 받는 쪽에서는 **사용하지 않음**.
  받는 사람이 카테고리를 직접 선택/추가한다(개인 설정을 강요하지 않음). 편집기 카테고리 칸은 비어 있음.

## 설계

### 1) 링크 & payload 포맷
- 형식: `https://kcc.sidore.org/e/<payload>` (폴백 `catholiccalendar://e/<payload>`).
- `<payload>` = **base64url( UTF-8( JSON ) )**. 단건 개인 일정 DTO:
  - `v` (스키마 버전 = 1, 필수)
  - `d` (시작일 `YYYY-MM-DD`, 필수)
  - `ed` (종료일 `YYYY-MM-DD`, 다일 일정일 때만)
  - `t` (시작 시간 `HH:mm`, 없으면 종일)
  - `et` (종료 시간 `HH:mm`, 선택)
  - `n` (카테고리 이름, 전달용 - 받는 쪽 미사용)
  - `c` (카테고리 색 ARGB int, 전달용 - 받는 쪽 미사용)
  - `m` (메모, 선택)
  - **미포함**: 알림(reminders)/notify(받는 사람이 자기 설정), 반복(recurrence)/feast, saint 필드, id.
- null/기본값 필드는 생략해 링크 길이를 줄인다(`ed`=`d`면 생략, 종일이면 `t`/`et` 생략, 빈 메모 생략).
- 한글은 UTF-8 base64url로 안전. 메모 100자 제한이라 URL 길이는 여유(단건 수백 자 수준).

### 2) 인코딩/디코딩 - 순수 함수 (신규 `lib/features/sharing/`)
- `Uri buildShareUri(CalendarEvent e)` : 위 DTO 구성 -> JSON -> base64url -> `https://kcc.sidore.org/e/<payload>`.
- `String buildShareText(CalendarEvent e)` : 사람이 읽는 요약 + 링크.
  예: `[가톨릭 달력] 8월 10일 오전 9:00 일정을 공유했어요\n(메모: 9시 미사 후 성가대 연습)\n내 달력에 추가: https://kcc.sidore.org/e/...`
  (카테고리명은 넣지 않음 - 사소.)
- `SharedEventDraft? parseShareUri(Uri uri)` : https(host `kcc.sidore.org`, path `/e/<payload>`) 또는 커스텀
  스킴에서 payload 추출 -> base64url 디코딩 -> JSON -> 검증. 실패 시 null 또는 오류 종류 반환.
- `SharedEventDraft` : `{ date, endDate?, time?, endTime?, memo?, categoryName, categoryColor, version }`.
- 검증: `v` 지원(1). `d`는 `YYYY-MM-DD`, `t`/`et`는 `HH:mm` 정규식. 메모 길이 클램프(<=100). 알 수 없는 키 무시.
  `v`가 지원 범위보다 크면 "앱 업데이트 필요" 신호.

### 3) 보내는 쪽 흐름
- 상세화면(`day_detail_view.dart`)의 개인 일정 행에 "공유" 아이콘/액션 추가(축일 행 제외 - 개인 일정만).
- 탭 -> `buildShareUri` + `buildShareText` -> `share_plus`의 `Share.share(text)` 로 OS 공유 시트.
- (일정 등록 직후 공유: 저장하면 상세로 돌아와 그 행의 공유 버튼으로 바로 공유 가능 - 별도 UI 불필요.)

### 4) 받는 쪽 흐름
- `app_links` 패키지로 링크 수신:
  - 콜드스타트: `AppLinks().getInitialLink()` (첫 프레임/라우터 준비 후 처리).
  - 실행 중: `AppLinks().uriLinkStream` 구독.
- 앱 루트(라우터 상위)에 링크 핸들러:
  1. `parseShareUri(uri)` -> `SharedEventDraft`.
  2. 유효하면 **일정 편집기를 "추가 모드"로 열고** draft로 자동 입력:
     - 채움: 날짜(`d`), 종료일(`ed`), 시간(`t`), 종료시간(`et`), 메모(`m`).
     - 비움: 카테고리(사용자가 직접 선택/추가). `n`/`c`는 디코딩만 하고 UI에 사용하지 않음.
  3. 사용자가 카테고리 선택 후 저장 -> 새 `CalendarEvent`(새 id, 알림 기본 `[1일 전]`, notify 기본,
     recurrence none)로 add -> 저장 후 **그 날짜 상세화면으로 이동**.
  - 유효하지 않으면 스낵바/다이얼로그로 안내(4항 에러 처리).

### 5) 편집기 변경 - `event_editor_sheet.dart`
- 현재 `showEventEditor(context, {date, existing})`는 `existing`이 있으면 **수정 모드**(저장 시 update).
- 신규: **"값이 채워진 새 일정 추가 모드"** 진입점 추가. 예:
  `showEventEditor(context, {date, SharedEventDraft? draft})` 또는 별도 `showEventEditorFromShare(context, draft)`.
  - `draft`가 있으면 `_isEditing = false`(새 id로 add), 필드만 draft 값으로 초기화, 카테고리 미선택.
- 기존 `existing`(수정) 경로와 분리해 회귀 없이 동작.

### 6) 네이티브 / 호스팅 설정
- **iOS**: `Runner.entitlements`에 Associated Domains `applinks:kcc.sidore.org` 추가. Info.plist의 커스텀
  스킴은 유지(폴백). AASA에 쓸 **Team ID** 필요.
- **Android**: `AndroidManifest.xml`의 MainActivity에 intent-filter 추가 -
  `android.intent.action.VIEW` + `BROWSABLE` + `DEFAULT`, `android:scheme="https"`,
  `android:host="kcc.sidore.org"`, `android:pathPrefix="/e"`, `android:autoVerify="true"`.
  커스텀 스킴(`catholiccalendar`) intent-filter도 폴백으로 추가. assetlinks에 쓸 **서명 SHA256** 필요.
- **Cloudflare (`kcc.sidore.org`)**: Worker 라우트/커스텀 도메인으로 연결하고 서빙:
  - `/.well-known/apple-app-site-association` (JSON, 확장자 없음, `content-type: application/json`),
    appID `<TeamID>.com.sidore.catholiccalendar`, `paths: ["/e/*"]`.
  - `/.well-known/assetlinks.json` (package `com.sidore.catholiccalendar` + SHA256 지문).
  - `/e/*` **랜딩 페이지**(HTML): payload 디코딩해 일정 요약 표시 + 스토어/앱에서 열기 버튼(미설치 폴백).

### 7) 미설치 폴백
- 앱 설치 시: 유니버설/앱링크가 앱을 바로 엶.
- 미설치/브라우저/데스크톱: `/e/<payload>` 랜딩이 일정 요약(payload에 담긴 카테고리명 포함 가능) +
  스토어 버튼 표시. **주의**: 앱이 아직 스토어 미출시라 출시 전엔 폴백이 제한적 -> 랜딩에 "곧 출시"/
  테스트 배포 링크로 임시 대응.

## 주요 파일
- 신규: `lib/features/sharing/` - `share_link.dart`(build/parse + `SharedEventDraft`),
  `share_link_handler.dart`(app_links 수신 -> 편집기 오픈), 필요 시 provider.
- 수정: `event_editor_sheet.dart`(추가 모드 draft 진입점), `day_detail_view.dart`(개인 일정 행 공유 버튼),
  `pubspec.yaml`(`share_plus`, `app_links` 추가), 앱 루트 위젯(링크 핸들러 연결).
- 네이티브: `ios/Runner/Runner.entitlements`, `ios/Runner/Info.plist`, `android/.../AndroidManifest.xml`.
- 호스팅: `kcc.sidore.org` 워커/라우트(AASA, assetlinks.json, `/e/*` 랜딩). (server/ 확장 또는 신규 워커.)

## 에러 처리
- 손상/형식 오류 payload -> "링크가 올바르지 않아요" 안내(크래시 없음).
- 지원보다 높은 `v` -> "앱을 업데이트해 주세요" 안내.
- 입력 검증: 날짜/시간 형식, 메모 길이 클램프, 알 수 없는 필드 무시(방어적).
- 중복 추가(같은 일정 두 번) 허용(MVP). 콜드스타트 vs 실행 중 수신 모두 처리.

## 범위 밖 (YAGNI)
- 카카오 링크 리치 카드 SDK, 축일 공유, 반복 규칙 공유, 다건 공유, 공유 만료/취소, 서버 저장.
- 받는 쪽에서 payload의 카테고리(`n`/`c`) 사용(담아만 두고 미사용).

## 선행조건 (사용자 제공 값)
- iOS **Team ID**(AASA appID용).
- Android **서명 인증서 SHA256**(assetlinks.json용; 디버그/릴리스 각각).
- `kcc.sidore.org`를 Cloudflare에 서브도메인으로 추가하고 Worker에 연결.

## 검증 (End-to-End)
1. 단위: `buildShareUri`/`parseShareUri` 왕복 - 한글 카테고리/메모, 종일 vs 시간, 다일, `ed`/`t`/`et`/`m`
   생략 케이스, 버전 필드, 손상 입력(빈/비base64/잘못된 JSON/높은 v) 방어.
2. 단위: `SharedEventDraft` -> 편집기 초기값 매핑(카테고리 미선택, 날짜/시간/메모 채움), 저장 시 새 id add.
3. 위젯: 상세화면 개인 일정 행에 공유 버튼 노출(축일 행엔 없음). 편집기 추가 모드가 draft로 채워짐.
4. 수동(네이티브): 실기기에서 https 링크 탭 -> 앱 열림(iOS/Android), 미설치 시 랜딩/스토어. AASA/assetlinks
   유효성(Apple/Google 검사 도구) 확인.
5. `flutter analyze` 무경고, `flutter test` 통과.

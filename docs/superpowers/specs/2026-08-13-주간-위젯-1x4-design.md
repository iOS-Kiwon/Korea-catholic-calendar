# 주간 위젯(1x4) - 설계 (Design)

작성일: 2026-08-13
브랜치: `feature/위젯_1_4`

## Context

홈 화면 위젯에 **이번 주 7일을 가로 한 줄로 보여주는 1x4 크기**를 추가한다. 기존 4x4 월간 달력
위젯의 한 행만 떼어낸 형태다.

현재 위젯 구성:

| 크기 | 프로바이더 | 내용 |
|---|---|---|
| 2x2 | `TodayWidgetTwoByTwoProvider` | 오늘 날짜 + 전례일 + 일정 (세로 배치) |
| 4x4 | `TodayWidgetFourByFourProvider` | 월간 달력 격자 6행 × 7열 + 월 이동 버튼 |

두 프로바이더 모두 `TodayWidgetProvider`(721줄)를 상속하고, 실제 렌더링은 companion object의
`buildViews`가 크기(`minWidth`/`minHeight`)로 모드를 판정해 분기한다.

### iOS는 대상이 아니다

WidgetKit이 허용하는 홈 화면 위젯 크기는 `systemSmall`(2x2) / `systemMedium`(4x2) /
`systemLarge`(4x4)뿐이고 크기를 임의로 정할 수 없다. **iOS에는 4x1 홈 화면 위젯이 존재하지
않는다.** 따라서 이 기능은 Android 전용이며, iOS(`ios/TodayWidget/TodayWidget.swift`,
`.supportedFamilies([.systemSmall, .systemLarge])`)는 그대로 둔다.

플랫폼별로 제공하는 위젯 종류가 달라지는 것은 감수한다.

## 확정된 결정 (사용자 확인)

- **대상**: Android만.
- **크기**: `targetCellWidth=4`, `targetCellHeight=1`.
- **내용**: 오늘이 속한 주의 7일. 요일 헤더 + 날짜 숫자 + 일정/전례일 텍스트.
- **칸 구성**: 4x4 격자 칸과 동일(`buildDayCell` / `today_widget_day_cell.xml` 재사용).
- **주 이동 없음**: 항상 이번 주만 보여준다. 탭하면 앱이 열린다(2x2와 같은 동작).
- **달 경계 주**: 다음(이전) 달 날짜도 **진하게**, **전례일 이름과 전례색까지 함께** 노출한다.

### 주 이동 버튼을 넣지 않은 이유

1x4의 실제 높이는 약 62dp다(4x4의 `minHeight=250dp` ÷ 4셀). 요일 헤더 14dp + 날짜 숫자 16dp +
텍스트 3줄 약 27dp로 이미 57dp를 쓴다. 4x4는 이동 버튼 헤더에만 36dp를 쓰므로 들어갈 자리가 없다.

좌우 끝에 세로로 세우는 방법은 터치 영역(20×62dp)이 확보되지만 칸 폭이 43dp에서 37dp로 줄고,
"사용자가 이동해 둔 상태에서 자정이 지나면 어느 주를 보고 있었는지" 상태를 관리해야 한다. 달력을
넘겨 보는 용도는 4x4 위젯이 이미 담당하므로 넣지 않는다.

### Dart 코드는 바뀌지 않는다

`WidgetSnapshotService`가 이미 `months` 배열에 **±12개월치 42칸 격자**를 담아 네이티브로 보낸다.
주간 위젯에 필요한 데이터가 모두 들어 있으므로 스냅샷 스키마를 건드릴 필요가 없다. 이 작업은 Android
리소스 + Kotlin 변경만으로 끝난다.

## 설계

### 1) 오늘이 속한 주 찾기

`snapshot.month`(앱이 스냅샷을 저장한 시점의 달)를 쓰면 안 된다. 8월 31일에 앱을 열고 한 달간 열지
않으면 9월 14일이 8월 격자에 없어 주를 찾지 못한다.

대신 **오늘 날짜로 달을 계산해 `months` 배열에서 찾는다.**

```
todayKey("yyyy-MM-dd") → 연/월 파싱 → monthSerial(year, month)
  → findMonthBySerial(snapshot, serial)
  → 그 격자 42칸에서 todayKey의 인덱스를 찾는다
  → row = index / 7
  → days[row*7 .. row*7+6]  (7칸)
```

`monthSerial`, `findMonthBySerial`은 이미 있는 private 헬퍼를 그대로 쓴다. 이 방식이면 앱을 열지
않아도 **±12개월 범위에서 정확**하다. ACTION_ITEMS에 기록된 4x4의 알려진 한계("달이 바뀌는 자정에
다음 앱 실행 전까지 이전 달 격자를 보일 수 있음")를 주간 위젯은 겪지 않는다.

`months`에서 달을 못 찾거나(±12개월 밖) 격자에 오늘이 없으면 빈 목록을 반환하고, 호출부는
`snapshot.month` 격자로 폴백한다. 그마저 실패하면 위젯은 요일 헤더만 그린다(빈 칸 7개).

### 2) 달 경계 주 - 셀 보정

주가 두 달에 걸치면(예: 8/31~9/6) 8월 격자의 마지막 행에 9/1~9/6이 `inMonth=false`로 들어 있다.
이 셀들은 두 가지 문제가 있다.

**첫째, 전례일 이름이 비어 있다.** 스냅샷 생성 코드가 이렇게 되어 있다
(`widget_snapshot_service.dart` `_dayPayload`):

```dart
final notable = inMonth && isNotableDay(day);
'liturgicalTitle': notable ? liturgicalTitle : '',
```

**둘째, 날짜 숫자가 흐리게 그려진다.** `dayNumberColor(weekday, inMonth, isToday)`가 `inMonth=false`를
회색으로 처리한다.

월간 달력에서는 맞는 동작이지만, 주간 위젯에서는 7일 모두 "이번 주"라 어색하다.

**해결: 각 칸을 그 날이 속한 달의 격자에서 다시 찾는다.** 9월 1일은 9월 격자에 `inMonth=true`로
있고 `liturgicalTitle`도 채워져 있다.

```
resolveWeekDayCell(snapshot, dateKey, fallback):
  dateKey에서 연/월 파싱 → monthSerial → findMonthBySerial
  그 격자에서 dateKey가 같고 inMonth=true인 셀을 찾아 반환
  못 찾으면 fallback(원래 행의 셀) 반환
```

**`titleFull`을 쓰지 않는 이유:** 스냅샷에는 `notable` 필터를 거치지 않은 `titleFull` 필드도 있다.
이걸 쓰면 보정 없이 전례일 이름을 채울 수 있지만, **평일까지 전부 이름이 뜬다**("연중 제19주간
화요일" 등). 4x4 격자는 주요 전례일만 표시하므로, 주간 위젯도 같은 기준을 지키려면 보정 방식이
맞다.

**색상은 이중으로 보장한다.** 보정이 성공하면 `inMonth=true`라 자동으로 진하게 나오지만, 폴백된
경우에도 흐려지지 않도록 `buildDayCell`에 `forceInMonth: Boolean = false` 파라미터를 추가하고 주간
위젯에서는 `true`로 넘긴다. 기존 4x4 호출부는 기본값을 쓰므로 동작이 바뀌지 않는다.

### 3) 어느 모드로 그릴지 판정

크기가 아니라 **프로바이더 클래스**로 판정한다.

```kotlin
val provider = appWidgetManager.getAppWidgetInfo(appWidgetId)?.provider?.className
val mode = if (provider == TodayWidgetFourByOneProvider::class.java.name) {
    WidgetMode.Week
} else {
    widgetMode(minWidth, minHeight)
}
```

크기 기반 `widgetMode`로는 구분할 수 없다. 1x4는 `minWidth≥250, minHeight<110`인데, 이는 "2x2를
가로로 늘린 것"과 같은 조건이라 `WidgetMode.WideShort`로 판정된다. `buildViews`가 이미
`appWidgetManager`를 인자로 받고 있어 추가 배선 없이 얻을 수 있다.

`WidgetMode`에 `Week`를 추가하고, `buildViews`의 `when`에 분기를 더한다. 크기 기반 판정
(`widgetMode` 함수)은 손대지 않는다.

### 4) 렌더링 - `buildWeekViews`

```kotlin
private fun buildWeekViews(
    context: Context,
    snapshot: JSONObject,
    todayKey: String
): RemoteViews
```

`today_widget_week.xml`을 만들고, `today_widget_month_rows`에 해당하는 행 컨테이너에
`today_widget_month_row.xml` 하나를 넣은 뒤 7칸을 `buildDayCell(..., forceInMonth = true)`로 채운다.
루트에 `openAppIntent`를 건다(이 부분은 `buildViews` 공통 코드가 이미 처리).

### 5) 레이아웃 - `today_widget_week.xml`

세로 `LinearLayout`, 배경은 기존 `@drawable/today_widget_background` 재사용.

**세로 예산을 먼저 따진다.** 1x4의 높이는 약 62dp다. 4x4처럼 상하 패딩 7dp를 주면 실사용 공간이
48dp밖에 남지 않는다. 세로가 귀한 위젯이므로 **상하 패딩만 4dp로 줄이고 좌우는 7dp를 유지**한다
(칸 폭 계산은 4x4와 같게 두기 위해서다).

```
62dp - 상하 패딩 8dp = 54dp 실사용
  요일 헤더      16dp   (11sp 텍스트 + 여유)
  날짜 숫자      16dp   (day_cell의 고정 높이)
  일정/전례일    22dp   (7.5sp 기준 약 2.4줄)
```

| 요소 | 높이 | 비고 |
|---|---|---|
| 요일 헤더 (`일`~`토`) | 16dp | 4x4의 `@style/TodayWidgetWeekday`(11sp bold) 재사용. 4x4는 22dp지만 축소 |
| 날짜 행 컨테이너 | `0dp, weight=1` | `today_widget_month_row.xml` 1개를 넣는다 |

칸 내부(`today_widget_day_cell.xml`)는 손대지 않는다. 날짜 숫자 16dp(13sp) + 제목
(7.5sp, `maxLines=3`, `ellipsize=end`)이 그대로 적용된다.

**텍스트는 2줄 남짓 보인다.** 한글 7.5sp에 `includeFontPadding=false`면 줄 높이가 약 9dp이므로
20dp ÷ 9dp ≈ 2.2줄이다. 설계 논의 중 제시한 목업은 3줄이었으나 실측 기준으로는 과하다.

**4x4는 이보다 좁다.** 같은 기준으로 계산하면 250dp - 패딩 14dp - 헤더 36dp - 요일 22dp = 178dp를
6행이 나눠 약 29.7dp/행이고, 셀 패딩 2dp와 날짜 숫자 16dp를 빼면 제목에 **11.7dp(약 1.3줄)**만
남는다. 즉 주간 위젯이 4x4보다 오히려 한 줄 더 보여준다. 두 위젯의 모양이 어긋나는 것이 아니라
1x4가 세로로 더 여유로운 것이다.

런처가 1셀 높이를 더 작게 잡는 기기에서는 그보다 덜 보일 수 있다. `maxLines` + `ellipsize`가 이미
걸려 있어 레이아웃이 깨지지는 않는다. 이 한계는 감수한다.

### 5-1) 위 계산의 전제 - minHeight는 하한선이지 실제 높이가 아니다

`minHeight`는 "이 크기 이상이어야 배치할 수 있다"는 하한선이고, 레이아웃이 `match_parent`이므로
위젯은 **런처가 실제로 준 높이를 다 쓴다.** 런처와 기기에 따라 4x4가 250dp보다 훨씬 클 수 있고,
그런 기기에서는 4x4도 이미 2줄 이상 보이고 있을 것이다.

따라서 위 줄 수 계산은 **최악의 경우**로 읽어야 하며, 실기기 확인 전에는 단정할 수 없다.

### 6) 위젯 등록

`today_widget_4x1_info.xml`:

```xml
<appwidget-provider
    android:description="@string/today_widget_4x1_description"
    android:initialLayout="@layout/today_widget_week"
    android:minWidth="250dp"
    android:minHeight="40dp"
    android:previewLayout="@layout/today_widget_week_preview"
    android:targetCellWidth="4"
    android:targetCellHeight="1"
    android:updatePeriodMillis="43200000"
    android:widgetCategory="home_screen" />
```

`minHeight`를 40dp로 낮게 잡아 셀 높이가 작은 런처에서도 배치되게 한다. `updatePeriodMillis`는
기존 두 위젯과 같은 12시간.

`TodayWidgetFourByOneProvider.kt`는 기존 두 서브클래스와 같은 3줄이다:

```kotlin
package com.sidore.catholiccalendar

class TodayWidgetFourByOneProvider : TodayWidgetProvider()
```

`AndroidManifest.xml`에 receiver를 기존 두 개와 같은 형태로 등록한다.

`strings.xml`에는 기존 위젯들과 같이 **이름과 설명 두 개**를 추가한다(receiver의 `android:label`이
이름을, `appwidget-provider`의 `android:description`이 설명을 쓴다).

```xml
<string name="today_widget_4x1_name">주간 전례력 4x1</string>
<string name="today_widget_4x1_description">이번 주 전례력과 개인일정을 한 줄로 보여줍니다.</string>
```

### 7) 자정 갱신 연결

`refreshAllWidgets`가 프로바이더를 명시적으로 나열하므로 여기에 추가해야 한다. 빠뜨리면 자정에
주간 위젯만 갱신되지 않는다.

```kotlin
val components = listOf(
    ComponentName(context, TodayWidgetTwoByTwoProvider::class.java),
    ComponentName(context, TodayWidgetFourByFourProvider::class.java),
    ComponentName(context, TodayWidgetFourByOneProvider::class.java)  // 추가
)
```

`midnightPendingIntent`는 2x2 리시버로 명시적 인텐트를 보내고 거기서 전체를 다시 그리는 구조라
그대로 둔다.

**토요일 → 일요일 자정**에는 오늘이 다음 행으로 넘어간다. 위젯이 매번 `todayKey`로 행을 다시
계산하므로 자동으로 처리된다. 별도 로직이 필요 없다.

## 범위 밖 (YAGNI)

- iOS 대응(4x1 홈 위젯이 플랫폼에 없음).
- 이전/다음 주 이동, "오늘" 버튼.
- 위젯 리사이즈 지원(`resizeMode`). 기존 두 위젯도 고정 크기다.
- 주 시작 요일 설정. 앱 전체가 일요일 시작 고정이고 스냅샷 격자도 그 기준으로 생성된다.
- 스냅샷 스키마 변경, 주간 전용 payload 추가.
- 위젯 설정 화면(configure activity).
- **4x4 본문 2줄화(아래 참조).**

### 보류: 4x4 본문 2줄화

4x4의 제목 영역을 2줄로 늘리는 것은 이번 작업에 넣지 않는다. 최악의 경우 기준으로 2줄에 닿게
하려면 조절할 곳이 전부 필요하고, 그래도 아슬아슬하다.

| 조절 | 행당 이득 | 누적 제목 높이 |
|---|---|---|
| 현재 | - | 11.7dp (1.3줄) |
| 셀 패딩 1dp → 0dp | +2dp | 13.7dp |
| 루트 패딩 7dp → 4dp | +1dp | 14.7dp |
| 요일 헤더 22dp → 16dp | +1dp | 15.7dp |
| 상단 헤더 36dp → 30dp | +1dp | 16.7dp |
| 날짜 숫자 16dp → 15dp | +1dp | 17.7dp (1.97줄) |

전부 적용해도 1.97줄이라 제목 폰트를 7.5sp → 7sp로 낮추는 것까지 필요하다. 그리고 상단 헤더와
요일 헤더를 줄이면 **이미 사용 중인 위젯의 외형이 눈에 띄게 바뀐다.**

게다가 5-1절에서 적었듯 실제 기기에서는 이미 2줄이 나오고 있을 수 있어, 손대는 것 자체가 불필요한
변경일 가능성이 있다. **실기기에서 현재 몇 줄이 보이는지 측정한 뒤 별도로 판단한다**(검증 10번).

## 검증

**자동 테스트로 잡을 수 있는 것이 거의 없다.** 이 프로젝트에는 Kotlin 단위 테스트가 없고, 이번
변경은 Dart 코드를 건드리지 않는다. `flutter test`는 회귀 확인 용도일 뿐이다. 실기기/에뮬레이터
확인이 실질적인 검증 수단이다.

1. `flutter analyze` 무경고, `flutter test` 전체 통과(회귀 확인).
2. `flutter build apk --debug` 또는 `./gradlew assembleDebug` 성공.
3. 위젯 목록에 1x4 항목이 뜨고, 미리보기가 보이며, 홈 화면에 배치된다.
4. 이번 주 7일이 요일 헤더와 열이 맞게 표시되고, **오늘 칸에 연한 주황 배경**이 온다.
5. 일정이 있는 날에 일정 텍스트가, 없는 날에 주요 전례일이 전례색으로 표시된다.
6. **달 경계 주 확인(핵심)**: 기기 날짜를 8/31 또는 9/1이 포함된 주로 맞추고, 다음 달 날짜가
   **진하게** 나오는지, **전례일 이름과 전례색이 함께** 나오는지 확인한다.
7. 자정 갱신: 기기 시간을 자정 직후로 옮겨 오늘 표시가 옮겨가는지, **토요일 → 일요일 자정에 다음
   주로 넘어가는지** 확인한다.
8. 위젯을 탭하면 앱이 열린다.
9. 2x2 / 4x4 위젯이 기존과 동일하게 동작하는지 확인(`buildDayCell` 시그니처 변경의 회귀).
10. **줄 수 실측**: 같은 기기에서 4x1과 4x4가 각각 본문 몇 줄을 보여주는지 세어 기록한다. 4x4가
    이미 2줄이면 "보류: 4x4 본문 2줄화"는 그대로 닫고, 1줄이면 그때 조절 범위를 정한다.

# 주간 위젯(1x4) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 오늘이 속한 주 7일을 가로 한 줄로 보여주는 Android 1x4 홈 화면 위젯을 추가한다.

**Architecture:** 기존 `TodayWidgetProvider`(companion object에 모든 렌더링이 모여 있는 open class)에 `WidgetMode.Week` 분기를 더한다. 4x4 월간 격자의 칸 렌더링(`buildDayCell`, `today_widget_day_cell.xml`)과 행 컨테이너(`today_widget_month_row.xml`)를 그대로 재사용하고, 오늘이 속한 행 하나만 그린다. 모드 판정은 크기가 아니라 프로바이더 클래스명으로 한다.

**Tech Stack:** Android AppWidget(RemoteViews), Kotlin. Flutter/Dart 코드는 변경 없음.

**설계 문서:** `docs/superpowers/specs/2026-08-13-주간-위젯-1x4-design.md`

## Global Constraints

- **Android 전용.** iOS에는 4x1 홈 화면 위젯이 존재하지 않으므로 `ios/TodayWidget/TodayWidget.swift`는 건드리지 않는다.
- **Dart 코드를 건드리지 않는다.** 스냅샷(`WidgetSnapshotService`)에 이미 ±12개월 격자가 들어 있어 스키마 변경이 필요 없다.
- 기존 2x2 / 4x4 위젯의 **동작과 외형이 바뀌면 안 된다.** `buildDayCell`에 파라미터를 추가할 때 반드시 기본값을 두어 기존 호출부가 그대로 컴파일되게 한다.
- 주 시작은 **일요일**이다(앱 전체 고정, 스냅샷 격자도 같은 기준).
- 달 경계 주에서 다음/이전 달 날짜도 **진하게 + 전례일 이름 + 전례색**으로 보여야 한다.
- 주 이동 버튼은 넣지 않는다. 위젯을 탭하면 앱이 열린다.
- 새 레이아웃의 루트 id는 반드시 `@+id/today_widget_root`여야 한다. `buildViews`의 공통 코드가 이 id에 클릭 인텐트를 건다.
- `flutter analyze`는 **Kotlin을 검사하지 않는다.** Kotlin 컴파일 확인은 APK 빌드로만 가능하다.

- [ ] **Step 3: 주 찾기와 셀 보정 함수 추가**

`buildDayCell` 함수가 끝나는 `}` 바로 다음에 세 함수를 추가한다.

```kotlin
        /// 오늘이 속한 주(일~토)의 7칸을 돌려준다. 찾지 못하면 빈 칸 7개.
        ///
        /// snapshot.month(앱이 스냅샷을 저장한 시점의 달)가 아니라 오늘 날짜로
        /// 달을 계산해 months(±12개월)에서 찾는다. 그래야 앱을 열지 않은 채 달이
        /// 바뀌어도 올바른 주를 그린다.
        private fun findWeekDays(snapshot: JSONObject, todayKey: String): List<JSONObject> {
            val days = monthGridForDate(snapshot, todayKey)
                ?: snapshot.optJSONObject("month")?.optJSONArray("days")
                ?: return List(7) { JSONObject() }

            var index = -1
            for (i in 0 until days.length()) {
                if (days.optJSONObject(i)?.optString("dateKey") == todayKey) {
                    index = i
                    break
                }
            }
            if (index < 0) return List(7) { JSONObject() }

            val rowStart = (index / 7) * 7
            return (0 until 7).map { col ->
                val raw = days.optJSONObject(rowStart + col) ?: JSONObject()
                resolveWeekDayCell(snapshot, raw)
            }
        }

        /// dateKey("yyyy-MM-dd")가 속한 달의 42칸 격자. months에서 찾는다.
        private fun monthGridForDate(snapshot: JSONObject, dateKey: String): JSONArray? {
            if (dateKey.length < 7) return null
            val year = dateKey.substring(0, 4).toIntOrNull() ?: return null
            val month = dateKey.substring(5, 7).toIntOrNull() ?: return null
            return findMonthBySerial(snapshot, monthSerial(year, month))
                ?.optJSONArray("days")
        }

        /// 달 경계 주 보정.
        ///
        /// 주가 두 달에 걸치면 다음(이전) 달 날짜가 inMonth=false로 들어온다.
        /// 그런 칸은 Dart 쪽에서 liturgicalTitle을 비워 보내고(notable = inMonth &&
        /// isNotableDay) 날짜도 회색으로 그려진다. 그 날이 속한 달의 격자에서 같은
        /// 날을 다시 찾아 온전한 칸으로 바꾼다.
        private fun resolveWeekDayCell(
            snapshot: JSONObject,
            fallback: JSONObject
        ): JSONObject {
            if (fallback.optBoolean("inMonth")) return fallback
            val dateKey = fallback.optString("dateKey")
            val days = monthGridForDate(snapshot, dateKey) ?: return fallback
            for (i in 0 until days.length()) {
                val day = days.optJSONObject(i) ?: continue
                if (day.optString("dateKey") == dateKey && day.optBoolean("inMonth")) {
```

## 실기기 검증 (코드 작업 이후, 사용자 몫)

자동 테스트로 잡을 수 있는 것이 없다. 이 프로젝트에는 Kotlin 단위 테스트가 없고 Dart 코드는 바뀌지 않는다. 아래는 실기기/에뮬레이터에서 눈으로 확인해야 한다.

1. 위젯 목록에 "주간 전례력 4x1"이 뜨고 미리보기가 보이며, 홈 화면에 배치된다.
2. 이번 주 7일이 요일 헤더와 열이 맞게 표시되고, **오늘 칸에 연한 주황 배경**이 온다.
3. 일정이 있는 날엔 일정 텍스트가, 없는 날엔 주요 전례일이 전례색으로 나온다.
4. **달 경계 주(핵심)**: 기기 날짜를 달이 바뀌는 주(예: 8/31이 포함된 주)로 맞추고, 다음 달 날짜가 **진하게** 나오는지, **전례일 이름과 전례색이 함께** 나오는지 확인한다.
5. 자정 갱신: 기기 시간을 자정 직후로 옮겨 오늘 표시가 옮겨가는지, **토요일 → 일요일 자정에 다음 주로 넘어가는지** 확인한다.
6. 위젯을 탭하면 앱이 열린다.
7. **회귀**: 2x2 / 4x4 위젯이 기존과 똑같이 보이고 동작한다.
8. **줄 수 실측**: 같은 기기에서 4x1과 4x4가 각각 본문 몇 줄을 보여주는지 세어 기록한다. 설계 문서의 "보류: 4x4 본문 2줄화"를 닫을지 판단하는 근거가 된다.
